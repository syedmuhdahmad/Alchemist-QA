## Decisions

| Question | Decision |
| --- | --- |
| Single source | `plugins/qa/routing.yaml`: work-item id patterns, routes, and depth by risk level |
| Where the tables live | In a new `routing` skill that the lead preloads. Agent bodies stay under 60 lines and hold no knowledge. |
| What the hook does | Adds a hint in plain code, with no model call. It only advises: the agent decides. |
| Where the hook speaks | Only in a project with `qa/profile.yaml`, so other repositories see nothing |
| What CI measures | The plain-code matcher on the golden set, at least 95%, on every pull request |
| How Claude's routing is checked | One eval case per route, generated from the golden set and run locally. CI has no Claude key. |

## Matching

- Signals match case-insensitively, as whole words.
- The route with the most matching signals wins. A tie goes to the longer match. A tie that a work-item id settles goes to that id's route. Any other tie is offered as a choice.
- An id picks its route only when no signal matched. Azure DevOps and Jira ids are recognised but have no route until their adapters exist.
- A slash command is never routed.

## Generated files

`tools/routing/build.mjs` writes:

- `plugins/qa/skills/routing/routing.json`, which the hook reads;
- the route and depth tables in `plugins/qa/skills/routing/SKILL.md`;
- `plugins/qa/evals/routing/<route>/`, one model eval case per golden prompt marked `model: true`.

It checks that every agent, skill, and route it names exists. A test fails while any generated file is out of step.
